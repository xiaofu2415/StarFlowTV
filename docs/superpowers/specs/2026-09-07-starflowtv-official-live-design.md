# StarFlowTV 官方直播类目设计规格

日期：2026-09-07  
状态：已获用户确认，待实现

## 1. 目标

在不改变 StarFlowTV 现有直播遥控器体验的前提下，新增独立的“官方直播”类目。类目首批覆盖央视官方直播页提供的 CCTV-1～17、CCTV-5+、CCTV-4 亚洲/欧洲/美洲入口；能够在有稳定、已验证的官方直链时使用现有全屏播放器，没有直链时使用官方网页播放。

当前 IPTV 类目保留不变，仍作为备用来源。官方类目不得把社区中转地址伪装成官方源，也不得执行绕过 DRM、登录、付费墙或地区限制的逻辑。

## 2. 研究结论与取舍

截图中的三个开源项目采用了三种互补方式：

- DongYuTVWeb 将频道分组与播放器类型分离；普通频道使用 m3u8，自定义播放器可以在 WebView 中执行页面脚本生成临时播放地址，也可以直接打开官方页面。
- CCTV_Viewer 以 X5 WebView 为核心，把 CCTV 频道映射到官方网页并提供电视遥控器频道列表。
- WebViewTvLive 使用 WebView、可更新的频道清单和多来源配置；其文档同时说明 WebView 首帧较慢、画质选择受限、部分官方站点存在非直播时段。

StarFlowTV 不直接引入远程任意 JavaScript。第一版只使用内置的央视官方页面白名单，并为稳定官方直链预留适配入口。这样可以保留官方来源的真实性，同时避免远程脚本更新破坏直播或引入不可审计行为。

## 3. 交互设计

`LivePlayActivity` 继续作为唯一直播容器，不另起一套官方直播首页。官方类目与现有直播类目共享以下行为：

| 操作 | 行为 |
| --- | --- |
| 上/下 | 在当前类目内切换频道，跨类目策略保持现状 |
| 左/右 | 继续使用线路/来源操作；官方频道没有备用线路时显示轻提示，不改变当前频道 |
| OK | 打开现有频道列表 |
| 菜单 | 打开现有直播设置，包括手动拉取源 |
| 返回 | 返回或退出的现有逻辑 |
| 冷启动 | 恢复上次播放的类目和频道 |

官方直链播放时继续显示现有播放器、频道信息、加载快照、EPG 和错误提示。官方网页播放时 WebView 只替换视频表面，频道列表、焦点、遥控器事件、返回行为和错误提示仍由 `LivePlayActivity` 管理。

网页播放可能保留央视页面自身的控件或宣传内容；应用不承诺移除官方页面内容，也不把官方页面中的宣传内容误报为 StarFlowTV 广告。

## 4. 播放架构

### 4.1 频道模型

为 `LiveChannelItem` 增加官方播放元数据：

- `officialChannelId`：稳定的内部 ID，例如 `cctv-1`、`cctv-5plus`、`cctv-4-europe`。
- `officialPageUrl`：央视官方直播页地址。
- `officialDirectUrl`：可为空；只有通过源流水线验证的公开官方 HLS 地址才能填写。
- `officialPlaybackMode`：`NONE`、`DIRECT` 或 `WEB`。

内置 `OfficialLiveCatalog` 生成一个名为“官方直播”的 `LiveChannelGroup`。网页地址作为可回退地址保存在频道项中，因此远程 IPTV 配置失败时仍能显示官方类目。

### 4.2 播放路由

新增一个小型 `OfficialLivePlaybackController`，由 `LivePlayActivity` 调用：

1. 频道有已验证的 `officialDirectUrl` 时，交给现有 `VideoView`，沿用现有播放器类型、请求头和错误策略。
2. 没有直链或直链失败时，在直播布局的 WebView 容器中加载 `officialPageUrl`。
3. WebView 只允许 `tv.cctv.com` 及央视页面加载所需的同源静态资源；外部跳转拦截并留在当前频道。
4. 切回 IPTV 频道时释放 WebView、恢复 `VideoView`；切换官方频道时复用同一个 WebView，避免重复创建内核。
5. 官方播放失败时先重载当前官方页，再回退到官方直链/官方页，不自动切换到未经验证的社区源。

### 4.3 生命周期

播放器路由必须在频道切换、后台、返回、配置刷新和 Activity 销毁时释放资源。WebView 不得阻塞直播配置下载，不能影响 VOD 模块启动；现有 IPTV 播放路径保持原样。

## 5. 数据与更新

第一版内置 21 个央视官方入口，作为无网和远程配置损坏时的安全回退。现有签名直播配置继续负责 IPTV 源热更新、缓存和回滚；官方目录的结构保留后续接入同一签名清单的能力，但第一版不下载远程脚本、不执行远程代码。

官方入口的来源域名和路径在单元测试中固定校验：必须是 HTTPS、主机为 `tv.cctv.com`，并且路径位于 `/live/` 下。配置出现空名称、重复 ID、非 HTTPS 或非央视域名时整组回退到内置目录。

## 6. 安全与合规边界

- 不解析或伪造登录 Cookie、私人 Token、家庭 IPTV 凭据。
- 不绕过 DRM、账号认证、付费墙或地区限制。
- 不从远程地址下载并执行任意 JavaScript、JAR 或 APK。
- 官方页面中的内容由央视站点提供；StarFlowTV 只负责打开白名单页面和管理电视遥控器交互。
- 诊断日志对 URL 查询参数和请求头继续脱敏。

## 7. 测试与验收

自动测试覆盖：

1. 央视目录包含 21 个唯一 ID，名称和 URL 对应正确。
2. 非 HTTPS、非 `tv.cctv.com`、非 `/live/` 地址被拒绝。
3. 有直链时选择 `DIRECT`，直链为空或失败时选择 `WEB`。
4. 官方类目上下换台只移动一个频道，不重复处理 key-up。
5. IPTV → 官方网页 → IPTV 切换时播放器和 WebView 资源状态正确。
6. 远程配置损坏时官方内置目录和当前 IPTV 缓存均保留。

设备验收使用现有 TCL 电视：安装新签名版本后，确认官方类目可见，CCTV-1/CCTV-5+/CCTV-4 亚洲至少能打开官方页面，上下换台不跳台，返回和菜单行为与现有直播一致。

## 8. 版本与交付

本功能版本目标为 `versionName 1.4.0`、`versionCode 6`。继续使用现有生产签名身份，构建 `java32` APK，并在可复现构建通过后生成 SHA-256 和发布元数据。此前工作区中关于手动拉取直播源、遥控器 key-up 处理的未提交改动不得丢失或回退。

## 9. 非目标

- 不把所有官方网页强行转成稳定 m3u8；官方页面没有公开稳定直链时保持网页播放。
- 不重写现有 IPTV 解析、自动换源、EPG 或 VOD 引擎。
- 不从截图中的资源集合网站复制未经验证的第三方源。
